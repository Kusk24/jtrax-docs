# UI/UX audit — what's broken across the front-ends

**Date:** 2026-08-21 · **Repos:** jtrax-admin, jtrax-web-app, jtrax-mobile-app
**Status:** triaged. Fixes shipped in jtrax-admin #60 #61 #64 #77 #78,
jtrax-web-app #41 #43 and jtrax-mobile-app #8. Everything still listed as open
below is open. **Last reconciled against the code: 2026-08-24.**

Two audits, one per app group, hunting things that make a user think *"that's
broken"* rather than style opinions. Findings were spot-checked against the
code before being written down — one was a false positive and is recorded as
such at the bottom.

## The pattern behind most of it

Almost every serious finding is one of three shapes:

1. **A control that reports success without doing anything.** "Reset password"
   said a link had been sent and sent nothing. "Finish Attendance" throws every
   tick away. The receptionist's whole check-in desk writes to local state.
2. **Mock data rendered as if it were live.** Not in a demo mode — in the
   signed-in product, indistinguishable from real data.
3. **Screen state that only exists in React**, so refresh, Back and shared
   links all lose it.

  - **A game's detail is a full page**, not a 460px drawer — #77,

## Open — controls that lie or lose data (console)

- **Student edit saves 3 of its 12 fields.** `StudentsPage.tsx:1479` sends
  `name`, `date_of_birth`, `current_level` only. Guardian name, phone, email,
  LINE id, class, branch, membership are collected and dropped.
- **Payment Status and Reference are discarded** (`PaymentPage.tsx:426`), and
  status is hard-coded `"Paid"` at `:621`.
- **Payment method filter can never match** what the console writes:
  `"Credit Card"` vs the stored `"CreditCard"` (`:45` vs `:620`).
- **Tournament wizard says "{name} is live" before anything is saved**
  (`TournamentPage.tsx:309`), then drops both fees, the date, format, time
  control and chief arbiter (`:1089`, `:1072`, `:129`).
- **Academy: teacher Status is collected and never sent.** The picker is at
  `AcademyPage.tsx:896`, but a teacher is read as `"Active"` at `:135` and
  drafted as `"Active"` at `:227` — there is no column for it. Badge, Icon and
  the class type are fixed; this third of the finding is not.
- **Teacher accounts are created with a password nobody is ever shown**
  (`AcademyPage.tsx:699`) — every other role gets the temporary-password modal.
- **Registration drops the guardian when only a phone was given**
  (`StudentsPage.tsx:976` accepts it, `:1409` requires name + email).

## Open — refresh, Back and deep links

- ~~`/parent/child/<id>` 404s on refresh; parent notifications link to mock
  child ids~~ — both fixed in #43: no mock keys are ever held, and
  notifications derive from real attendance rows.
- The 4-step tournament registration flow is `useState` — Back exits the flow
  and reload restarts it empty.
- The student portal's `?screen=` is read once and never written; Home and the
  puzzle board have no URL.
- Console screens still holding navigation state in `useState`: Students
  (including a half-filled wizard), Parents, Payments (the date range), Class
  history, Academy, Admins, Games, the LINE inbox. `lib/url-state.ts` (#60) is
  the tool; they each need wiring.

## Open — consistency

- **Loading vs empty:** half the console lists show "nothing here" while
  fetching; `AdminsPage.tsx:157` inverts it and says "Loading…" forever when
  genuinely empty; Academy's card views have no empty state at all.
- **Delete confirmation is uneven** — unlinking a guardian, removing a child
  from a session and unlinking a Lichess account all fire instantly from a bare
  ✕, while comparable actions confirm.
- **Search and pagination** exist on six list pages and are absent on Admins,
  Academy and Announcements.
- **Row detail is still three different things** (full page, centred modal,
  right drawer) for the same "I clicked a row". Games moved from a drawer to a
  page in #77, but both other shapes survive: the Academy course and teacher
  open a centred `Modal` (`AcademyPage.tsx:549`, `:594`) and a tournament
  participant opens a right drawer (`TournamentPage.tsx:833`).
- **Back paths differ per screen** in the portals: `router.back()`, a fixed
  push, and pure state all coexist; mobile's back *pushes*, growing the stack.

## Open — Intl and localisation

- `jtrax-admin/lib/live.ts:50` — money is `Intl.NumberFormat("en-US")` plus a
  hand-appended `" THB"`; `:46` pins dates to `en-GB`; `:332` hand-rolls a
  12-hour clock; `theme.ts:139` is an English month array.
- `PaymentPage.tsx:595` computes the page total by stripping non-digits from an
  **already formatted** string — `"1,500.50 THB"` becomes `150050`.
- Payment methods, class/level/relation/branch options and admin status render
  as raw English in the Thai UI (the parents screen translates the identical
  relation list, which is what makes it inconsistent).
- Portals: `ParentData.tsx:36` pins `en-GB`; fees are built as `` `THB ${n}` ``
  then re-parsed; several dates are assembled by string surgery.
- Almost no ICU `plural` — "1 days", "1 mins", "1 credits left", "All 1 students".

## False positive, checked and dismissed

The teacher home was flagged for saying "You have one class today" beside "My
Classes (2)". Those are different facts — one class *today*, two in total — and
the screen is coherent. Left alone.

## Suggested order

1. Controls that lie or lose data (above) — they cost staff real work.
2. Replace the mock teacher portal and the parent fallback with live data, or
   label them plainly as demo.
3. Wire `useUrlBackedState` through the remaining console screens.
4. One pass for Intl/plurals; one pass for empty/loading consistency.
